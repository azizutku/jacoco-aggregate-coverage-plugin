# 0.2.0

### Added
- Configuration-cache coverage on Gradle 8.4 and 9.7.1.
- Isolated Projects support on Gradle 9.7.1.
- Functional tests using reports generated by JaCoCo 0.8.15.
- Negative functional coverage for missing, disabled, empty, and malformed module reports.
- Android Gradle Plugin 9.4.0 and JVM integration coverage.
- Configurable aggregate output through `aggregatedReportDirectory`.
- Report variant publishing when the plugin is applied to a participating subproject.

### Changed
- Require Java 17 and update the build to Gradle 9.7.1, Kotlin 2.4.20, and current tooling.
- Use each `JacocoReport` task's declared HTML output directory when available.
- Resolve module reports through project dependencies instead of accessing subproject task models.
- Select report tasks in their producing subprojects while retaining the root task-name setting as
  an optional global override.
- Reuse the report assets generated by the active JaCoCo version instead of bundled stale assets.
- Generate portable module paths and correct breadcrumbs for nested projects.
- Precompute table rankings and use `Long` coverage counters.

### Fixed
- Remove every `Project` API call from task execution so the plugin supports Gradle's
  configuration cache.
- Remove cross-project task and layout access so the plugin supports Isolated Projects.
- Fail clearly when configuration or HTML reports are missing instead of logging and succeeding.
- Track participating projects separately so lenient variant resolution cannot hide missing reports.

### Deprecated
- Move custom report paths from the root `configuredCustomReportsDirectory` and
  `configuredCustomHtmlOutputLocation` properties to the producing subproject's
  `jacocoAggregateReport` registration.
- Replace the root `jacocoTestReportTask` override with project-local `reportTaskName` selection.
